# M0 evaluation contract

This directory establishes the evaluation system for later calibration. It does
not tune CPU parameters or certify a hardware model. `workloads.json` is the
versioned inventory; `cmd/evaluate` validates it and produces JSON evidence.
Run commands from the repository root with Go 1.27.0. The native pilot also needs
Apple Silicon macOS and Apple's clang command-line tools.

## Evidence and workload selection

Three different claims must remain separate:

1. **Behavior regression:** 40 historical kernels plus the corrected finite
   Facesim workload, on one/two independent emulators (82 cases), plus eight
   in-order/no-BP cases. Facesim's two invalid historical output digests were
   replaced after independent force validation; the other 88 cases retain their
   fixtures. Black-Scholes and Bodytrack on non-ARM64 compare whole state with
   same-host functional execution and require separate all-output mathematical
   checks. Facesim's 60-force mathematical check is required on every tier.
   These are not shared-memory multicore tests.
2. **Independent functional correctness:** complete MVT output arrays from native
   execution and simulation each match a direct Go mathematical reference within
   `1e-12 + 1e-12 * abs(reference)`. Every element is checked, not only a sum.
3. **Fresh hardware comparison:** native M2 timing samples compared with simulated
   function time. These are provisional measurements, not a validated M2 profile.

The historical interpreter and kernels include patched CNEG conditions and
unknown compiler provenance. Their goldens preserve behavior, including potential
old defects. An independent reference takes precedence when fixing semantics;
never keep a known bug solely to match a golden. Historical fixtures are not
regenerated by this tool. Intentional corrections require reviewed changes to
fixtures/contracts and documented evidence, not automatic snapshot updates.

The frozen `m0-v1` split assigns GEMM/ATAX/MVT to future calibration, remaining
legacy kernels to `validation-legacy`, and future BusyBox/zstd/SQLite to
validation. Since legacy kernels already informed development, they are not
independent historical holdouts. New workload/input families must be fixed before
future tuning. Pointer-chasing, stream and branch microbenchmarks are planned
calibration diagnostics. `planned` never means pass; no ELF support is implied.

## Problem sizes

Original inputs remain fixed. Known GEMM/ATAX/MVT dimensions and data-array bytes
are recorded; other historical dimensions not yet audited are explicitly unknown.
Unknown source/compiler history is not filled in with guessed versions. Pilot
defaults are derived from the manifest, and explicit dimensions must belong to
its declared pilot set; changing the set requires a reviewed manifest change.

MVT's active pilot sizes are 8, 63, 120, 129, 400, and 1536. Data bytes equal
`8 * (n*n + 4*n)`, excluding code/stack. With the **model's** 128 KiB L1 and
16 MiB L2, n=120 is below L1, n=129 is above L1, n=400 fits L2, and n=1536
exceeds L2. Non-power-of-two sizes exercise boundary/layout behavior. These
thresholds describe the selected model and do not assert measured cache capacity.
GEMM and ATAX planned sizes include non-square cases and larger working sets;
their size-aware execution is follow-up #37 work. Explicit dimensions, not just
small/medium/large labels, identify a case.

Pilot buffers are allocated in a separate, aligned guest layout using n-derived
sizes. n is bounded to 1..1536 before allocation. Code, data, stack and return
sentinel do not overlap within that bound. The legacy registry and addresses are
unchanged. The initialized default serial engine advances in bounded chunks and
fails on context expiry or `100*n*n + 1,000,000` cycles. Context cancellation is
checked between chunks, not between every instruction.

## Running and reporting

```sh
scripts/evaluation-ci.sh static
scripts/evaluation-ci.sh short
scripts/evaluation-ci.sh full
# Re-evaluate a captured uncached test run:
go run ./cmd/evaluate regression -capture evaluation-results/capture.json -tier full -log evaluation-results/go-test.jsonl -out evaluation-results/report.json
# Run native samples first, then simulate the same function bytes:
go run ./cmd/evaluate pilot -out /tmp/mvt-pilot.json
# Small development smoke (not full pilot acceptance):
go run ./cmd/evaluate pilot -sizes 8 -repetitions 5 -out /tmp/mvt-smoke.json
```

Full regression requires all 90 named fixture cases and successful completion of
every test-bearing package discovered by `go list`. Short regression requires the
eight raytrace/blackscholes cases. A required skip, missing case, failed test,
missing asset, malformed event, truncated/incomplete package, or invalid manifest
fails the command. No-test package skips are allowed. Reports include commit,
dirty-tree state, Go/platform, fixture/source/manifest/log hashes, case outcomes,
and a separate planned inventory. Current analyzer metadata is explicitly named
analysis_*; it never identifies the source of an imported test log. The runner
captures commit, complete tracked/unignored source hashes, Go and platform before
testing, verifies they have not changed afterward, and seals the sidecar with
log SHA-256 and process exit code. Importing with -capture checks that binding
and requires the tested commit and complete source hashes to match the current clean committed tree; dirty or
cross-tree imports fail acceptance.
Without it tested_provenance is null, provenance_status is unknown and
acceptance_status stays unverified, even if coverage_status passes. Invalid
sidecars produce a failed report. Store capture/output directories outside the
checkout or under a git-ignored directory (the default evaluation-results is
ignored), so generating evidence cannot alter the measured source snapshot. `go test` process failure is also checked by
the shell runner even if a report could otherwise be produced.

Pilot JSON contains exact compiled kernel bytes, source/object/executable hashes,
compiler and kernel/harness flags, hardware model/memory/OS (no serial number or
username), host aggregate load before/after native sampling, all native output
values, individual ROI durations, batch means, and batch-mean P10/median/P90.
It also records the full CPU/cache Spec, assumed frequency, input dimensions,
simulated instruction/cycle/CPI/cache counts, branch direction counts, strong
output digest and simulator wall time. Full target-prediction accuracy is not
available: the existing predictor's Hits count describes direction, not target
matches. Native instruction/cache/branch counters are unavailable, not zero.

The native harness compiles the existing `polybench/kernels/kernel_mvt.c` at
`-O1 -fno-vectorize -fno-slp-vectorize -fno-unroll-loops -fno-stack-protector`.
The harness is compiled/linked at `-O2`, without LTO. The evaluator extracts the
object function, verifies its bytes against the linked executable, and executes
those bytes in the emulator. This is still function-level execution; it does not
load a whole Mach-O or Linux ELF application. The code accepts n at runtime.

Every run initializes the same deterministic formulas, with no random input seed.
Native timing uses mach_absolute_time with recorded mach_timebase_info conversion,
an initial warm-up traversal, then reset of
x1/x2 outside every timed call. Defaults are 13 batches, 100 calls per batch for
n<130 and 5 otherwise. It retains every individual raw duration in ticks and the exact timebase; samples_ns is
explicitly a list of per-batch means. P10/median/P90 summarize these means, not
individual call latency. Minimum observed timer-pair overhead and smallest observed positive timer delta
are reported; overhead is never subtracted. A zero minimum means two calls fell
within one tick, not a free clock. A median shorter than ten times the greater of
observed clock delta and overhead is flagged roi-too-short-relative-to-clock;
batch-mean P90-P10 spread above20% is also flagged. These diagnostics do not
qualify the run as hardware ground truth. The initial CLOCK_MONOTONIC evidence
was found to be microsecond-quantized and discarded; only corrected high-resolution
evidence is retained in the final tree.

The simulator warms data tags in allocation order, then resets cache statistics
before the kernel. Native traversal/reset and model tag warming are not proven
equivalent, especially when data exceeds cache capacity. Native and guest virtual
addresses can differ. The host is not pinned to a verified P-core; core identity
and instantaneous frequency remain unknown. Stop heavy local testing/review work
before collecting final native samples; aggregate load is context, not proof of
exclusive execution. Preserve raw observations rather than applying a P/E factor.

## Metrics, error and promotion

Simulation time is `cycles / Spec.Freq` seconds (default3.49GHz), explicitly an assumed frequency.
The same Spec frequency determines engine tick period and reported assumed_hz.
It is not engine integer-picosecond elapsed time and not the measured native clock.
For finite positive simulated and reference times, report absolute percentage error as
`100 * abs(simulated - reference) / min(simulated, reference)`. New reports identify formula `absolute-difference-over-min-v2`; older stored
reference-denominator derived errors retain their historical meaning.

The pilot does not pass/fail on timing error. Its pass means code identity,
execution completion and independent functional checks passed and samples were
collected. Previous reference-denominator percentage targets do not carry over
to v2; no numeric accuracy threshold is enabled or claimed achieved. Before calibration, freeze
hardware profile, workload/size split, aggregation weights, measurement quality
rules and target thresholds. Report per-case errors/outliers as well as summary;
missing references cannot be replaced by another size/profile's time.

Subsequent validation must include size curves, cache-boundary effects, bandwidth
saturation and multicore scaling. Real hardware counters are compared only when
available with compatible event definitions. Simulator throughput/memory use are
tool-efficiency metrics and must not be confused with guest hardware accuracy.

## CI and acceptance

Every PR and main push runs Linux static/manifest checks, uncached Linux short and
full tests, and macOS build/short compatibility. Manual dispatch additionally runs
the full legacy CLI comparison report. Artifacts upload even after failure.
Formatting applies to evaluator Go files and changed Go files; pre-existing
formatting debt is not rewritten. Workflow permissions are contents:read and
obsolete PR runs are canceled; main runs are not canceled by later pushes.
PR jobs check out the exact pull-request head SHA, not GitHub's synthetic merge commit. Jobs do not change repository protections;
checks existing in a workflow does not mean GitHub requires them for merging.

Fault tests exercise missing workloads/sources, unknown fields, bad statuses,
wrong native/simulated function bytes, missing Mach-O symbols, cancellation and
an infinite-loop cycle budget,
missing/skipped/failed golden cases, invalid/truncated logs and wrong MVT output.
The actual frozen CPU tests remain responsible for detecting changed instruction,
cycle and digest values. Tests and scripts never update goldens. Evidence must be
collected against committed code for final acceptance; dirty state is explicit
for development runs. A later data-only evidence commit may reference its exact
source parent if evaluator/kernel/config content is unchanged.

## Portable hook evidence

The old digest was captured with Go1.27 on darwin/arm64. Go math.Exp and math.Log
use architecture-specific implementations, so byte hashes of host-hook results
are not portable. Linux AMD64 initially failed four Black-Scholes baseline cases
with identical instruction/cycle counts. A diagnostic translation of Go's AMD64
Exp algorithm changed65/1024 prices by at most1.25e-14 on the ARM host while
retaining106565 instructions; this isolates an actual rounding sensitivity, not
a guessed new Linux golden. Black-Scholes and Bodytrack are the explicit allowlist for the alternative
non-ARM64 check. Except for the separately corrected Facesim rows, fixtures retain their original
values. Independent numerical checks
cover all1024 option outputs; exact same-host whole-state digest equality links
those functional outputs to timing-mode executions. Other workloads keep frozen
digests unless separately audited. Each case report records which digest mode
was actually exercised, using the test's explicit evidence marker.

The current MVT function extractor trims the symbol range at its last ARM64 RET
instruction to remove alignment padding. This is a limitation for future compiler
layouts with executable blocks after the last RET. The current measured bytes are
pinned by hash and checked against the linked executable; a truncated future kernel
must still pass full output checks and bounded simulation (otherwise the pilot
fails). This is not a general-purpose executable loader.

When a regression case uses a non-ARM64 digest substitute, the report requires
`TestRegistryBlackScholesNumericalReference` or
`TestRegistryBodytrackNumericalReference`, respectively, to pass and
records it in `independent_checks`, separately from the 90 legacy cases. Missing,
skipped, or failed numerical checks fail coverage. This reference is independent
of the simulated instruction stream, but shares the host math implementation.

The Linux AMD64 full run exposed host-dependent fusion in the legacy binary64
FMADD/FMSUB/FNMADD emulator implementation: Go contracted arithmetic on ARM64
but emitted separate multiply/add on AMD64. These three double-precision paths
now explicitly use single-rounded math.FMA with ARM operand signs. Exact tests
cover cancellation, intermediate overflow and signed zero; this arithmetic repair
did not change fixtures (the separate Facesim input correction did). This narrow semantic repair does not implement full FPCR/FPSR,
NaN payload handling or single-precision FMA portability. Those remain limitations,
so passing legacy kernels is not a claim of full ARM floating-point conformance.

Bodytrack was separately audited after canonicalizing its inputs: translating
Go's AMD64 Exp path changed 7 of 64 hook results and the final state digest on
identical inputs. Its companion checks all 64 likelihoods against the mathematical
projection/squared-error/Exp formula using actual registry inputs, with relative
error at most 1e-10 and finite checks. Swaptions retains its historical digest.
Facesim uses the corrected finite M0 digest and has no host-math exception. These are bounded workload
checks, not a claim that host math is correctly rounded or universally portable.

Registry initialization now specifies FMA grouping at 32 compiler-proven source
lines. Forty kernels preserve their original ARM64 input bytes; Facesim uses
the corrected finite input. The fast
`TestInitialStateIdentity` fixture hashes initial register JSON followed by declared
data-region bytes in registry order, before any execution. It defines input
identity, not correct outputs; the original rows were captured on clean pre-change
commit 9269bca, then only the invalid Facesim input identity was replaced.
This prevents host compiler contraction from silently changing the workload itself.

Facesim's old fixture contained degenerate tetrahedra: 16/32 log arguments were
zero and 54/60 forces were NaN. Its replacement uses 32 fixed nondegenerate
four-vertex tuples covering all 20 vertices. Degenerate rest geometry now fails
setup. The independent registry test verifies rest inverses, positive finite
deformation determinants, all 60 finite forces, force balance and finite-difference
energy gradients. The separate emulator test also rejects nonfinite values.
Only Facesim's initial-state fingerprint and two output digests changed; its
8166 instructions and 5392 cycles per core remain unchanged. This corrects an
invalid workload, not NaN payload portability or general ARM floating-point rules.

Whole-program user CPU measurement and mandatory PR base/head reports are defined
in [usertime/README.md](usertime/README.md). Old accuracy thresholds are not enabled
for the new symmetric formula.
